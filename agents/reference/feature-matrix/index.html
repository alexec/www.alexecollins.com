Feature matrix of coding-agent apps¶

This page lists every app the weekly competitor check has found that runs several coding agents at once, against the full set of features found across them. Agents is in bold, wherever its score puts it.

  • ● the app has it, in full.
  • ◐ it has part of it: only by hand, only in an alpha, beta or by request, only on some platforms or runtimes, or only through someone else's add-on.
  • ○ it does not.
  • ?⃝ unknown: the app's docs, changelog, README and code did not say either way.

Each table has a Score column, and its rows are sorted by it: ● counts 1, ◐ counts 0.5, and ○ and ?⃝ count 0, as a percentage of the table's features. An unknown counts as missing, so an app with thin docs scores low. Two features are shown but not scored: Browser or preview, since every agent already has a full browser on the computer, and Switch when allowance runs out, which Agents left out on purpose in favour of a new agent reading another's work.

A feature that comes from an MCP server is counted the same way for every app:

  • ● when the app itself shows it, including through a view drawn from the app's own server, such as Agents' ci board.
  • ◐ when a server from the app's own MCP catalogue gives the agent the feature, with nothing shown in the app. Every catalogue here carries Playwright, Linear, Jira and GitLab servers, as the official MCP registry does, so an app with a catalogue has at least ◐ for a browser the agent drives, trackers beyond GitHub and git hosts beyond GitHub.
  • ○ when it takes a server added by hand, or cannot be done.

Passing each runtime's own sandbox through counts as sandboxed tools: an app is not marked down for a runtime that has none. Overall score, after the tables, adds every feature up.

The matrix was filled in on 2026-10-12 from each app's own docs, changelog, README, releases and, where open, source. Agents' row was last brought up to date on 2026-10-13. Every app is held to the same bar, Agents included: a ● needs the whole feature, documented by the app itself, and a ○ needs evidence, such as an app that ships for macOS alone having no Android app. Every Monday, after the Competitor check, the Feature matrix workflow (.agents/workflows/feature-matrix.md) brings it up to date from the week's merged changes and the Competitor check's report. The reports in ~/.agents/reviews/competitors/ give the sources. Apps change every week, so check a row against the app before relying on it.

Where Agents falls short¶

Agents' ◐ cells, and why:

  • Runs with the computer off: nothing is lost when the Mac sleeps, but agents on it pause until it wakes, and agents on servers keep working where nothing can reach them while the Mac that runs the control plane sleeps. See The control plane.
  • End-to-end encrypted relay: Agents Host runs it when Relay for my devices is on. It has not yet been checked on a phone away from home.
  • Notifications: the Mac gets them. The relay takes them to the iPhone and iPad, which has not yet been checked away from home, and the web page gets none. See Phone and iPad.
  • Spending limits: in money or in tokens (#838), so only for runtimes that report a price or tokens. Cursor, Antigravity and Grok report neither, and run past every limit. See Limit spending.
  • Task board: the ci server's issues view lists GitHub issues in the app, with who has each one and Start Agent on each row. It has no columns, and an issue cannot be moved or edited there.
  • A browser the agent drives, trackers beyond GitHub, git hosts beyond GitHub: through Playwright, Linear, Jira and GitLab servers from the MCP marketplace, with nothing shown in the app. A GitLab server of Agents' own is parked (#813).

Agents has none of these at all:

  • Android app (#810), Windows or Linux desktop (#811).
  • Simulator panes, language servers.
  • Several accounts per runtime, teams.

What each feature means¶

Running agents

  • Several agents at once: Several agent sessions run at the same time.
  • A git worktree per agent: Each agent can work in its own git worktree and branch, made by the app.
  • Several runtimes: It runs more than one vendor's agent, such as Claude Code and Codex.
  • ACP: It speaks the Agent Client Protocol.
  • Runs with the computer off: Agents run on a remote or cloud machine, and can be reached, while the person's own computer is off.
  • End-to-end encrypted relay: A phone or browser away from home reaches the agents through a relay that cannot read them.
  • Notifications: Push or system notifications when an agent needs the person or finishes.

Following and answering

  • Shows who needs you: A status shows which agent is waiting on the person.
  • Sessions side by side: Several sessions are visible at once, in a split, grid or separate windows.
  • Sessions as a tree: Sessions are shown under the session that started them.
  • Send while it works: A message can be sent, queued or used to steer while the agent is working.
  • Voice or dictation: Prompts can be spoken.
  • Rich cards in replies: Agent replies can hold interactive cards, tables or charts, beyond Markdown.

Reviewing work

  • Diff review: The agent's changes can be reviewed as a diff in the app.
  • Pull requests: Pull requests can be created, reviewed and merged in the app.
  • Git hosts beyond GitHub: Pull requests and checks work with GitLab, Bitbucket or others too.
  • CI checks: CI status is shown or watched.
  • A second agent reviews: Another agent reviewing the first one's work is a feature of the app.

Tools in the app

  • Terminal: A terminal is built in.
  • Starts agents from issues: An issue starts an agent, or an agent is started from an issue in one step.
  • Trackers beyond GitHub: Linear, Jira or other trackers are connected in the app.
  • Scheduled or triggered runs: Agents start on a schedule or on an event.
  • Agents start agents: An agent can start and manage other agents.
  • The app's own tools for agents: The app gives its agents tools of its own, over MCP or a CLI.

Extensions, accounts and cost

  • MCP or skills catalogue: A catalogue or marketplace to add MCP servers or skills from.
  • Plugins: The app has plugins or extensions of its own.
  • Usage or cost: Usage, allowance or cost is shown.
  • Spending limits: Spending can be capped.
  • Several accounts per runtime: More than one account for the same runtime, such as two Claude logins.
  • Switch when allowance runs out (not scored): It moves to another runtime or account, by itself, when one runs out.

Organising

  • Labels or tags: Sessions or tasks can be labelled.
  • Pins: Sessions or tasks can be pinned.
  • Archive: Sessions can be archived.
  • Teams: Several people can use it together.
  • Open source: The app's source is under an open-source licence. Source-available counts as ○.
  • Self-hosted: It runs entirely on the person's own machines and servers.

## The apps
  • Agents: this project. Mac window, Remote on iPhone and iPad, web page, and agentsd hosts.
  • Agentastic: A closed-source native Mac IDE for many agents, with an iPhone companion and cloud agents.
  • Atelier (was Acepe): A young native editor for coding agents over ACP, Mac and Linux.
  • Claude Code: Anthropic's agent: CLI, desktop Code tab, web and mobile, with background agents and routines.
  • Claude Squad: A terminal app running agent CLIs in tmux, a worktree each.
  • CodeAgentSwarm: A closed-source desktop app supervising agent CLIs in grid panes, with a task board and budgets.
  • Codeg: An ACP-based desktop and web workspace with a self-hosted server.
  • Conductor: A Mac app running Claude Code and Codex in parallel workspaces, with cloud workspaces and an iOS app.
  • Cursor: An editor with an Agents Window, cloud agents, Projects and an iOS app.
  • DockTerm: An Electron terminal workspace around the claude CLI only.
  • Emdash: An open-source desktop app, a worktree per task, locally or on your own SSH hosts.
  • GitHub Copilot: The Copilot app, coding agent, Agent HQ and VS Code sessions.
  • Happy: An open-source harness with desktop, iOS, Android and web clients.
  • Helicon: An unofficial desktop, web and VS Code client for Meta's Muse Code CLI.
  • Maestro: An open-source (AGPL) orchestration command centre with event-triggered prompts.
  • Nimbalyst: A desktop, mobile and web workspace with a tracker, a wiki and session trees.
  • Nuphos: A team workspace over ACP, local, remote or in cloud containers.
  • OpenAI Codex: OpenAI's agent in the ChatGPT apps, the cloud and a CLI; open source and self-hosted apply to the CLI only.
  • Parallel Code: A desktop app with tiled tasks, Docker sandboxes and an Android app.
  • Paseo: An open-source daemon with desktop, iOS, Android, web and CLI clients.
  • Pragma: A desktop app with a task board, SSH remote projects and the Pragma Go mobile client.
  • ReevesAgents: TUI, local web UI and CLI running agent CLIs in tmux, with an MCP so one agent steers the others.
  • Roamgate: A web/PWA client for a Herdr terminal-multiplexer server.
  • Rove: A terminal app with a worktree per task, a daemon, a local kanban and iOS/Android bridges.
  • Sculptor: Imbue's desktop app for parallel agents, with a container backend and a CI babysitter.
  • Superset: A desktop app for parallel agents with its own task tracker, cloud workspaces and an iPhone app.
  • T3 Code: A local server driven from desktop, web, iOS and Android apps.
  • Threadlines: A T3 Code fork: desktop and Docker-server workspace, a worktree per thread.
  • tuios: A terminal multiplexer and tiling window manager with an agent-state rail and Inbox.
  • Vibe Kanban: A local web app whose kanban was retired in v0.1.44; the README says it is sunsetting.
  • VibeiDE: A paid, closed-source desktop app with task queues per project.
  • Warp: An agentic terminal with the Oz cloud-agent platform.
